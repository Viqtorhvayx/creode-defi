Abstract

Creode is a decentralized finance protocol built on Hedera. It bundles four products behind one non-custodial interface: a time-locked Vault, a single-asset Yield Hub, a peer-to-peer order-book exchange and CODE-weighted governance. The app never holds user keys or funds; every deposit, trade and vote is an on-chain transaction the user signs from their own wallet. Assets are Hedera Token Service (HTS) tokens, so token rules are enforced by network consensus rather than application code alone.

01. Overview

One protocol, four on-chain products

Each product is backed by its own audited-primitive smart contract deployed to Hedera Testnet. They share a treasury, a rewards system (CODE points) and a governance layer, but each settles independently on-chain.

Vault

Time-locked savings paying a fixed APY by asset tier over 7 / 30 / 60-day or custom terms.

Earn: Yield Hub

Deposit one token; the protocol auto-zaps it into a balanced dual-token yield position that compounds.

P2P Trading

An on-chain order book with escrowed limit orders: no house, no pool. Charts use live market data.

Community Governance

Hold CODE to open proposals and cast weighted votes; every tally is finalized on-chain.

02. Vault

Time-locked savings with fixed, tiered yield

Deposit native HBAR or any supported HTS token and lock it for a fixed term to earn a fixed APY. Yield accrues linearly and is paid from the protocol treasury. At or after maturity you withdraw your full principal plus accrued yield; custom terms interpolate between the tier rates.

03. Earn · Yield Hub

Single-asset yield, auto-zapped and compounding

The Yield Hub runs balanced dual-token liquidity positions without requiring you to hold both tokens. Supply one asset and the protocol builds the position for you:

  1. You deposit one token, for example HBAR.
  2. The SwapRouter, a constant-product AMM, swaps ~50% into the pair token to form a balanced ~50/50 position.
  3. The position is deposited into the CreodeYieldVault, which accrues yield. Live APY and TVL are derived from real on-chain custody and prices.

You can Compound accrued rewards back into your position, Supply More or Withdraw the full position on demand.

Auto-compounding via Hedera HIP-1215

Compound by hand with the Compound button, or flip Auto: On and let the protocol do it fully on-chain, using HIP-1215 generalized scheduled contract calls. A contract can schedule its own future calls through the Hedera Schedule Service, meaning native on-chain "cron" with no off-chain keeper.

  • You enroll a position with one cheap transaction, with no scheduling cost to you.
  • The CreodeCompoundScheduler runs a self-perpetuating tick: each scheduled tick compounds every enrolled position and schedules the next tick itself, so the loop continues with no keeper.
  • Scheduling cost is paid once by the protocol and amortized across all users. Every scheduled second must be strictly in the future, closing off infinite-loop abuse.
✓
Live on Hedera testnet and verified end-to-end. Scheduled ticks execute and re-arm themselves autonomously on-chain.
04. P2P Trading

A trustless, on-chain order book

P2P is a peer-to-peer spot exchange with no house and no pool. Every trade matches one user's order against another's, settled by the CreodeP2P escrow contract.

  • Limit order: you post a price; your sell side is escrowed in the contract until it fills, is cancelled or expires. Makers can always cancel to reclaim escrow.
  • Market order: fills the best-priced resting order immediately, with partial fills supported.
  • Long buys the base token with the quote; Short sells the base for the quote.
  • On each fill the taker pays the maker directly and the escrow is released minus a 0.20% protocol fee.

Because every order carries a fixed price, there is no AMM-style slippage. A 0.5% floor only guards each fill against dust rounding. Tradable pairs include HBAR-USDC, WBTC-USDC, WETH-USDC, SAUCE-USDC, DOVU-USDC and HBAR-SAUCE.

≈
Charts use real market data: Pyth Network for majors, SaucerSwap / GeckoTerminal for Hedera small-caps. Prices are live, not simulated.
05. Community Governance

CODE-weighted decisions, settled on-chain

Creode is steered by its holders. The CreodeGovernance contract stores every proposal, every vote and the final tally; nothing lives on a private server. Governance decides yield emissions, new vault and market assets, parameters and upgrade direction.

CODE is the governance token: voting weight is your live CODE balance at the moment you propose or vote, at a ratio of 1 CODE = 1 vote. On mainnet CODE is earned through real protocol usage; on testnet a one-time Claim CODE to vote lets anyone try the full flow.

  1. Propose: any holder of ≥ 1,000 CODE submits a title and description on-chain, opening a 3-day vote.
  2. Vote: CODE holders cast a single Yes or No, weighted by balance. One vote per address per proposal, enforced in-contract.
  3. Finalize: after the window closes, anyone can finalize. It passes only if total votes clear quorum and Yes exceeds No; otherwise it is rejected.
  4. Enact: passed proposals are signalling decisions; the role-gated admin then enacts the approved direction on-chain.
06. CODE Points

Rewards for real usage

CODE points reward genuine protocol activity. Every successful transaction that moves value through Vault, Earn or P2P earns CODE, weighted by the USD value moved:

  • A minimum of 5 CODE per protocol action.
  • Roughly 1 CODE per $10 moved: a $1,000 action earns ~100 and a $5,000 action ~500.
  • Faucet claims, approvals and plain transfers earn nothing.

Totals and per-transaction rewards are computed from real on-chain history and shown in the Activity tab.

07. Protocol Event Log

An independently-verifiable audit trail on Hedera Consensus Service

Alongside its EVM contracts, Creode writes a real-time protocol event log to a dedicated Hedera Consensus Service (HCS) topic. Every Vault deposit/exit, P2P order fill, and governance action is submitted to the topic the moment its underlying transaction confirms.

  • Tamper-evident ordering: HCS assigns each message a consensus timestamp and sequence number under Hedera's aBFT consensus, independent of any single API or database Creode operates.
  • Independently verifiable: the topic can be read directly from any Hedera Mirror Node — no trust in Creode's frontend required to confirm an event happened when it says it did.
  • Read live in-app: the Activity tab's Protocol Event Log panel surfaces these messages as they land, each linking to its underlying transaction on HashScan.

08. Security

Secured by Hedera HTS, hardened by proven primitives

Creode's assets are Hedera Token Service (HTS) tokens, not plain ERC-20s bolted onto an EVM. HTS enforces token rules at the network layer, below and independent of any application contract:

  • Native token controls: supply, freeze, wipe, pause and KYC keys are honored by consensus nodes themselves, so token rules can't be bypassed by a buggy or malicious contract.
  • Explicit association: an account must associate a token before receiving it, blocking unsolicited-token and dusting attacks by default.
  • Deterministic finality: Hedera's aBFT hashgraph consensus gives fast, final settlement with no re-org risk; a confirmed transaction cannot be rolled back.
  • Every HTS token also exposes the standard ERC-20 interface at its EVM address, so contracts interact normally while the network keeps enforcing token-level guarantees.

On top of that, the contracts use battle-tested building blocks: OpenZeppelin Ownable / AccessControl, ReentrancyGuard, Pausable and SafeERC20; non-custodial escrow in P2P; tamper-proof, one-vote-per-address governance; and role-gated, hard-capped admin functions.
